# Projetos 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar uma CLI local que organiza análise JavaScript, tarefas retomáveis e preparação de repositório independente com sufixo `-2.0`.

**Architecture:** Expandir a CLI existente com módulos pequenos de persistência, tarefas, análise e exportação. Reutilizar a integração REA sem executar código do alvo. Workspace privado e repositório exportável são separados.

**Tech Stack:** Node.js >=24.15.0, módulos ESM, node:test, Git, rea-agents 6.5.0; sem dependências novas de produção.

**Spec:** ../specs/2026-10-16-projetos-2.0-design.md

## Global Constraints

- Primeiro incremento: um alvo JavaScript local por vez; demais formatos ficam explicitamente sem adaptador.
- `schemaVersion: 1`; nome final `<nome>-2.0`; não sobrescrever destinos nem modificar o alvo.
- Workspace e destino não podem conter um ao outro nem ficar dentro do alvo; rejeitar links e redirecionamentos nos caminhos de escrita.
- Preservar licenças, controles de acesso e hashes; sem publicação de credenciais, configuração ou evidências privadas.
- Nenhuma chamada de modelo, instalação Plandex/Docker/WSL, serviço permanente ou publicação remota automática.
- Cada execução tem diretório e ID novos; falha e análise parcial não contam como conclusão.
- Defaults da análise existente: 300000 ms por fonte, 512 MiB, prazo externo com 120000 ms de margem; validar antes de iniciar.
- Preparar repositório local não cria funcionalidade automaticamente. Produto de demonstração é desenvolvido separadamente.

## Review Focus

- Perfil Windows e prefixos semelhantes: `alvo` versus `alvo-outro` não podem confundir contenção (tarefa 1).
- Disco cheio ou interrupção durante gravação: estado anterior legível ou erro explícito, nunca sucesso presumido (tarefa 1).
- Evidência alterada depois de concluir tarefa: relatório deve marcar referência inválida (tarefa 2).
- PID reutilizado ou inacessível após reinício: estado `unknown`, sem novo processo automático (tarefa 3).
- Falha de Git após criar arquivos: preservar preparação incompleta e impedir sobrescrita na retentativa (tarefa 4).

### Tarefa 2: tarefas e evidências

**Files:** Create tasks.mjs, report.mjs e tests/project-tasks.test.mjs.

**Interfaces:** `addTask(workspace,{title,acceptance,dependsOn=[]}): Task`; `setTask(workspace,id,{state,evidence?}): Task`; `readTasks(workspace): Task[]`; `buildReport(workspace): object`.

Task contém id UUID, título, acceptance, dependsOn, state, timestamps e evidence opcional `{path,sha256,verification:'operator-declared'}`. Estados permitidos: pending/running/blocked/done/failed. Sem runner de tarefas nesta entrega. `done` exige dependências concluídas e evidência válida; enumeração de dependentes impede retrocesso inconsistente. Mudanças ocorrem dentro de withProjectLock.
